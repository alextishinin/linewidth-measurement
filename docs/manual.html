1  System overview

This system measures the linewidth (FWHM) of a continuous-wave laser in real time. A Thorlabs SA210 scanning confocal Fabry-Pérot interferometer sweeps its cavity length with a piezo; every time the cavity passes through resonance with the laser, a transmission peak appears on the built-in photodiode. The SA201B controller generates the piezo ramp and amplifies the photodiode signal; a PicoScope 5242D digitizes it; and the Python application on this PC finds the peaks, calibrates the time axis into optical frequency, fits a Lorentzian to the main peak, and displays the linewidth live — together with its uncertainty, the cavity finesse, mode structure, and a running history. Every sweep is logged to CSV.

Figure 1 — signal chain.
QuantityValue

Resolution floor. The measured width is the laser lineshape convolved with the ~67 MHz instrument function. A laser much narrower than 67 MHz reads ≈67 MHz regardless — that result means “narrower than the instrument can resolve.” The app flags this state as instrument-limited and, for broader lasers, also shows a deconvolved estimate (measured − 67 MHz).

2.3 Optical layout

  • Mount the SA210 in the Ø1″ kinematic mount. Keep the input beam diameter around 1 mm.
  • Steer the beam with the fold mirror into the SA210's input iris; place the f = 100 mm lens so its focus lands at the cavity center, about 25 mm past the front flange. Good mode matching minimizes transverse modes (section 4).
  • Both irises on the SA210 help: close the input iris to center the beam, open the back iris while walking the mount.
Optical power. A few hundred µW to a few mW of CW power is plenty — the photodiode amplifier at its lowest gain (10k V/A) saturates around 5 V output well below damaging levels. If the app warns “signal saturating” at 10k gain, attenuate the beam. Consult the SA210 manual's damage threshold before sending in more than ~10 mW.

2.4 Power & bench notes

Three mains loads (SA201B, PC, monitor) run from one switched power strip mounted at the bench, so the whole station powers up together; the instruments enumerate over USB while the app's startup loop retries for up to a minute (section 3). The PC is dedicated to this instrument and launches the app automatically at logon.

3  Software installation & the kiosk setup

  1. Windows 10/11 with Python 3.12+ (winget install Python.Python.3.12).
  2. In the repository folder: pip install -r requirements.txt (installs numpy, scipy, PySide6, pyqtgraph, pyserial, picosdk).
  3. Install PicoSDK 64-bit from picotech.com/downloads — it provides ps5000a.dll. The default install path C:\Program Files\Pico Technology\SDK is what config.py expects; edit PICO_SDK_LIB there if yours differs.
  4. Wire the instruments per section 2.2, connect both USB cables, and run run.bat (or python linewidth_live.py). If your Python is installed elsewhere, edit the path inside run.bat.

Kiosk behavior on this bench PC

  • Auto-start: a shortcut named Linewidth Measurement in the user's Startup folder (shell:startup) launches run.bat at every logon; the window opens maximized. Delete the shortcut to disable.
  • Desktop icon: the same shortcut sits on the desktop for manual launch.
  • Startup retries: after power-up, USB instruments can take a while to enumerate. The app retries opening the hardware 12 times at 5 s intervals (~1 minute) before giving up with a diagnostic message.
  • Only one owner: close the PicoScope 7 desktop application before launching — only one program can hold the scope at a time.

4  Alignment procedure

  1. Start the app (live mode, sawtooth running). Click Align (or press t): the controller switches to a triangle scan — the waveform Thorlabs recommends for alignment — and the big headline switches from linewidth to peak height in volts.
  2. Center the beam: close the SA210 input iris, and steer the fold mirror until the transmitted spot is centered; open the iris again.
  3. Watch the Full sweep graph while walking the SA210 mount's tip/tilt: make peaks appear, then maximize their height. Tall, sharp, non-split peaks indicate good coupling.
  4. Now minimize the transverse modes percentage shown in the subtitle (and in the stats panel). Odd transverse modes of a confocal cavity appear exactly halfway between the main peaks; their relative height is a direct mode-matching meter: <5% good, 5–20% fair, >20% poor. Adjust tip/tilt and the lens focus position to push it down.
  5. Click Align again to return to the sawtooth and normal measurement. Alignment sweeps are never logged and never enter the history plot.
Peak height and mode purity are both alignment criteria: height first (signal), then purity (single transverse mode). A perfectly mode-matched confocal cavity shows only the main comb.

5.4 Readouts and the stats panel

Headline (large number): the linewidth FWHM in MHz with its 1σ uncertainty, e.g. 66.5 ± 1.3 MHz. In live mode this is the median of the last 11 sweeps (spike-free); in single mode it is that sweep's own value. In Align mode it becomes the peak height in volts.

Subtitle: the same width converted to wavelength units at the current λ (e.g. = 251 fm @ 1064 nm), plus either instrument-limited (reading is at the ~67 MHz floor) or an estimated deconvolved laser width.

Warning area (red): analysis problems (no signal…), signal saturation, scope ADC clipping, controller-write failures, USB disconnects, and missing-trigger conditions appear here and clear automatically.

6  Measurement modes

Live mode (default)

The scope captures every ramp; each triggered sweep is analyzed and displayed, the reported linewidth is the rolling median of the last 11 sweeps, and every sweep is appended to the session log. The history graph scrolls over the last 3 minutes (--history-s to change).

Single-sweep mode

Switch with Mode (m) or start with --single. The scope is completely idle — no data is acquired (the PicoScope LED stops flashing) until you press Run once (r), which arms exactly one capture (or N averaged sweeps with --avg N). The result freezes on screen; each run adds one point to the history, and old points never expire. Ideal for documenting discrete measurements.

Align mode

Overlay on either mode (t): triangle scan, peak-height headline, live transverse-mode meter, nothing logged. See section 4.

7  How the measurement works

7.1 From sweep to spectrum

The SA201B sweeps the cavity mirror with a sawtooth; the piezo moves λ/4 of mirror travel per free spectral range. The same laser line therefore re-appears every FSR, and the time between two repeats corresponds to exactly 10 GHz. The app measures that repeat period on every sweep and uses it to convert time to optical frequency — the frequency axis is self-calibrating and assumes nothing about the ramp slope.

7.2 The calibration guards

Finding the repeat period robustly is the heart of the instrument, because two effects can fool a naive search: the piezo's nonlinearity chirps the peak spacing across the sweep (spacings drift 10–20%), and a misaligned confocal cavity adds odd transverse modes exactly halfway between the fundamentals — a comb at FSR/2 that can look identical to the real one. The algorithm therefore:

  1. builds candidate periods from tall-peak spacings and from the sweep's autocorrelation (each candidate also doubled, in case the raw candidate was the half-FSR comb);
  2. rejects candidates that imply a finesse beyond ~1.5× the instrument spec — an impossibly good answer means the ruler is wrong — or that have no actual partner peak one period away;
  3. picks among the survivors using the piezo's nominal response (~10 V per FSR at 1064 nm, scaled by the λ-box value since piezo travel per FSR is λ/4) as a soft prior;
  4. measures the final spacing as the average of the left and right neighbor gaps of the analyzed peak, which cancels the chirp to first order;
  5. falls back to the median period of the last 20 sweeps if a single sweep's calibration deviates >4% (flagged cal-fallback in the log).

The analyzed peak itself is chosen deterministically — a competitive interior peak nearest the sweep center, sticky to the previously tracked one — because with several near-equal peaks, “the tallest” would be a per-sweep noise lottery.

7.3 Lorentzian fit, jitter, and the median

A Lorentzian is fitted to the analyzed peak; its FWHM in calibrated units is the linewidth. A single peak transit lasts only ~µs, so each sweep samples the instantaneous laser-cavity frequency jitter: raw per-sweep widths scatter by a few percent with occasional outliers. In live mode the app reports the median of the last 11 sweeps (~1.6 s of data; --median N to change, --median 1 for raw), which is spike-free — while the raw value of every sweep is still logged unmodified. The observed scatter is itself displayed, as it directly measures the jitter.

7.4 The uncertainty budget

The headline's ± is a 1σ error combining, in quadrature:

  • the Lorentzian fit's covariance on the width,
  • the frequency-calibration error — the standard error of the FSR peak spacing over the last 20 sweeps,
  • the standard error of the rolling median (1.253·σ/√N).

It is recorded in the log and in exported files.

8  Data: logging, export, snapshots, settings

Raw data is never altered. Statistics (the rolling median, the uncertainty) are always added in separate columns; the raw per-sweep measurement is logged unconditionally in every mode.

8.2 Export (on demand)

Export data (e) writes to exports\:

  • sweep_YYYYMMDD_HHMMSS.csv — the displayed sweep: columns time_s, signal_v, freq_offset_mhz, fit_v, preceded by a # metadata header (export time, λ, FSR, calibration slope, FWHM in MHz with 1σ, FWHM in wavelength units, finesse, transverse fraction, PD gain, mode).
  • history_YYYYMMDD_HHMMSS.csv — the linewidth trend: iso_time, elapsed_s, linewidth_mhz, linewidth_pm.

Works in live or single mode; the file names appear in the status area after a successful export.

8.3 Snapshots

s saves to logs\: a PNG screenshot of the whole window (in the active theme) and a raw CSV of the displayed sweep (time_s, signal_v) — a quick lab-notebook record.

8.4 settings.json (automatic persistence)

On every exit the app writes settings.json next to the program and restores it on launch: wavelength, theme, ramp amplitude / offset / sweep time / expansion, gain choice (auto or fixed index), the graph-2 x-range mode and manual bounds, and the full-screen state. Precedence at startup: explicit CLI flag → saved value → built-in default — so a one-off --wavelength-nm 780 wins for that session without overwriting your saved setup. Delete settings.json to return to factory defaults.

9  Measuring a different wavelength

9.1 Inside the current cavity's band (820–1275 nm): app only

Nothing physical needs to change. Type the new wavelength into the laser λ nm box and press Enter. This updates:

  • the Δλ display and all pm/fm conversions in exports and the log (Δλ = λ²·Δν∕c, so the same 67 MHz reads ~0.25 pm at 1064 nm but ~0.54 pm at 1550 nm);
  • the piezo calibration prior: the mirror moves λ/4 per FSR, so the volts-per-FSR figure scales linearly with λ. The prior only breaks ties between calibration candidates — the frequency axis itself is always measured from the peak repeats, so even a wrong λ cannot corrupt the linewidth. It just weakens the disambiguation.

Then re-align (section 4) — steering and focus are wavelength-dependent.

9.2 Outside the band (e.g. 1550 nm): swap the cavity head

The current SA210-8B mirrors and photodiode cover 820–1275 nm. For 1550 nm, swap the interferometer head for an SA210-12B (1275–2000 nm). All SA210-series heads share the same 10 GHz FSR and the same connections, so:

  1. Physically: swap the head in the same Ø1″ mount; reconnect its piezo cable to SA201B OUTPUT and its detector SMA to PD AMPLIFIER IN. The photodiode is built into the head, so the detector swap is automatic — the SA201B amplifier doesn't care.
  2. Optics: check every optic's coating for the new band. The bench's achromat is AR-coated 400–1100 nm — replace it with a 1050–1700 nm coated doublet of the same focal length; verify the fold mirror's coating covers 1550 nm (use an IR-band dielectric mirror, e.g. a 1280–1600 nm class coating, if not). An IR viewing card or camera is needed for alignment — the beam is invisible.
  3. In the app: type 1550 in the λ box. Done — no code changes, no CLI flags; the FSR is unchanged so the calibration works as before, and the prior scales itself.
  4. Re-align from scratch (section 4).

9.3 A different-FSR cavity (higher resolution)

Other Thorlabs scanning FP series (e.g. the SA200 family, FSR 1.5 GHz, resolution down to ~7.5 MHz) also work. Launch with the cavity's numbers, e.g.:

python linewidth_live.py --fsr-ghz 1.5 --instrument-mhz 7.5

Everything else — calibration, guards, display ranges, the “Full FSR” x-range label — follows those two flags automatically. Check the specific model's datasheet for its FSR, finesse, and wavelength band.

11  Troubleshooting

SymptomCause & fix
no trigger — is SA201B TRIGGER OUT connected… The scope's EXT input sees no ramp-start pulse. Check the TRIGGER OUT → EXT BNC and that the ramp is actually running (SA201B screen).
no signal — check laser alignment into the SA210 Triggered sweeps but no peaks above ~0.35 V at any gain: the beam misses the cavity, the laser is off/blocked, or the power is far too low. Re-align (section 4).
! signal saturating PD amplifier output at the 5 V rail: auto-gain will step down; at 10k V/A already, attenuate the beam.
! scope ADC clipped The digitizer range clipped a sample; usually accompanies saturation and clears when the level drops.
! SA201B USB disconnected — retrying… The controller's serial link dropped. Measurement continues (the ramp free-runs); the app reconnects automatically and re-applies amplitude, offset, sweep time, expansion, gain and waveform. Check the USB cable if it persists.
Startup fails with PICO_NOT_FOUND Another program owns the scope (close PicoScope 7), the USB cable dropped — or a previous process was force-killed mid-capture, which wedges the driver with a stuck request. In that last case only a reboot frees the unit. Prevention: always close the app with its window's ✕ or q; never end it from Task Manager while it is capturing. The app prints [exit] scope released on every clean shutdown.
App doesn't appear right after power-on USB enumeration can lag a cold boot; the launcher retries for ~1 min. If it gave up, double-click the desktop icon.
Peaks halfway between the main peaks Odd transverse modes — an alignment/mode-matching indicator, not extra laser modes. Minimize the transverse modes % (section 4). They are automatically excluded from the mode count and calibration.
More “modes” than expected, all equal height Verify the frequency axis before believing it: check that the peak pattern repeats ~once per 10 V of ramp (the SA210's nominal piezo response at 1 µm). Two laser modes spaced near FSR/2 (mod FSR) can mimic a doubled comb — perturb the laser (e.g. pump power): real two-mode beat spacing moves, the piezo's repeat spacing does not.
Linewidth reads ≈67 MHz and won't go lower That's the instrument floor — the laser is narrower than the SA210 can resolve (the subtitle says instrument-limited). The reading is an upper bound.
History shows occasional single-sweep spikes in the log Normal: raw sweeps sample µs-scale jitter (a few % scatter, ~3% of sweeps spike). The reported/displayed median is spike-free; both are in the log (section 8.1).

12  Maintenance, tests & specifications

Housekeeping

  • Logs grow: live mode writes several rows per second (~a few MB per hour). Old logs\session_*.csv files can be archived or deleted freely; the app never re-reads them.
  • Reset the configuration: delete settings.json (next to the program) to return every persisted control to its default.
  • Update the software: git pull in C:\linewidthmeasurement. Every push to the repository runs the analysis self-test in CI on Python 3.11–3.13.
  • Self-test: python test_analysis.py verifies the whole measurement pipeline against a synthetic laser — no hardware needed.
